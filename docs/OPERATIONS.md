# 운영 안내

운영자 한 명이 휴대폰으로 매일 확인하는 것을 기준으로 정리했다. 배포는 `docs/DEPLOY_KODEPLOY.md`, 구조는 `docs/ARCHITECTURE.md`.

## 매일 확인

1. **홈**: 다음 게시, "오늘 N / 목표 묶음", 오늘 올라간 X 게시물 수, **필요한 조치**(결과 확인 필요·답글 실패·X 연결·곧 비는 예약·검토 대기·생성 실패·예산)
2. **알림함**(상단 종): 같은 원인은 하나로 묶이고 횟수만 늘어난다. 콘텐츠 부족·예산 한도처럼 계속되는 상태는 해결되면 "해결됨"으로 닫힌다. 브라우저를 닫아도 서버가 계속 기록한다(실시간 푸시·이메일은 없다)
3. **게시 기록**(예약 → 시계 아이콘, 또는 설정 → 게시 기록): 진행 중·확인 필요·최근

## 켜고 끄기

| 하고 싶은 것 | 방법 | 효과 |
|---|---|---|
| 실제 게시 허용 | 서버 환경변수 `PUBLISHING_ENABLED=true` (재시작) | 처음에는 false. false면 예약이 와도 시작하지 않고 예약에 이유가 표시된다 |
| 자동 운영 시작·멈추기 | 홈 → 자동 운영 시작 / 멈추기 | 예약 게시와 자동 생성의 주 스위치. DB에 저장돼 재배포 후에도 유지 |
| 생성만 잠시 멈추기 | 홈 → 생성 일시정지 | 자동·버튼 생성 모두 멈춤. 만들어 둔 글은 계속 게시 |
| 게시만 잠시 멈추기 | 홈 → 게시 일시정지 | 새 묶음과 남은 답글을 보내지 않음. 지난 예약은 닫히고 글은 다음 빈 예약으로 |
| 운영 모드 | 설정 → 운영 모드 | 완전 자동 / 검토 후 게시(승인한 revision만) / 게시만 자동(직접 쓴 글만, 생성 안 함) |

예약 게시는 **실게시 허용 + X 연결 + 자동 운영** 셋이 모두 있어야 일어난다. 홈의 "예약 게시가 멈춘 이유"에 빠진 것이 보인다. 목업 모드에서는 실게시 허용과 무관하게 테스트 대역에만 기록된다.

## 알아 둘 개념

- **생성 시점 ≠ 게시 시점**: 생성은 설정한 방식(미리 정해진 시각에 / 예약 N분 전 / 재고 유지 / 게시할 때 / 버튼)으로 하고, 게시는 시간표의 예약 시각에 한다. 시간표를 바꿔도 이미 만든 글을 다시 만들지 않는다
- **콘텐츠 묶음 ≠ X 게시물**: "하루 20묶음"은 본문 + 자기 답글 묶음 20개다. 묶음 하나가 X 게시물 2개 이상일 수 있고(기본 본문 + 답글 1개, 길면 추가 답글), 예약 화면·홈·편집기에 실제 게시물 수를 따로 보여 준다
- **간격**: 본문 시작 기준 기본 간격(기본 30분) + 예약마다 한 번 정해 저장한 추가 지연. 늦게 시작하면 뒤 예약을 저장된 지연으로 늦춘다. 서버가 멈췄다 돌아와도 밀린 예약을 한꺼번에 올리지 않는다

## 문제 해결

### 답글이 실패했어요 (일부 완료)
본문은 이미 X에 있다. 게시 기록 → 그 묶음 → **실패한 답글부터 다시**(본문은 다시 올리지 않는다). 계속 실패하면(예: X 답글 제한 403) **그만두기** — 남은 답글은 보내지 않고 그 글은 자동 예약에서 빠진다.

### 결과 확인이 필요해요 (불명확)
보냈지만 응답을 못 받았다(시간 초과·서버 종료 등). X에는 같은 요청을 한 번만 처리하는 장치가 없어서 **자동으로 다시 보내지 않는다.**
1. X 계정에서 그 시각 근처의 게시물을 확인한다
2. 있으면 **올라가 있어요** → 게시물 주소(…/status/숫자)나 ID 입력 → 남은 답글이 그 게시물에 이어서 올라간다
3. 없으면 **안 올라갔어요** → 그 부분부터 다시 보낸다
4. 확인할 수 없으면 **확인 없이 다시 보내기**(중복 위험을 확인해야 진행) 또는 **그만두기**

### X 연결이 만료됐어요
설정 → 연결 → 다시 연결. 갱신 토큰이 거부되면 연결이 "만료"로 바뀌고 중대 알림이 남는다. 다른 계정으로 바꾸려면 먼저 연결 해제.

### 곧 게시할 글이 없어요
홈·알림의 "곧 게시할 글이 부족해요". 생성 설정(기본 프롬프트·생성 시점), 생성 일시정지, 예산 한도를 확인하거나 직접 등록한다. 생성 실패는 콘텐츠 → 문제 필터.

### 예약 시각이 됐는데 시작하지 않았어요
예약 카드에 "시작 못 함: 이유"가 보인다(실게시 꺼짐·연결 필요·일시정지·허용 구간 밖·앞 게시와 간격·예산). 이유를 고치면 유예 10분 안에서는 바로 시작하고, 지나면 닫히고 글은 다음 빈 예약으로 간다.

## 비용

- 화면의 금액은 **앱이 기록한 사용 횟수 × 설정의 요율표**로 계산한 추정치다. 환율·세금·할인·무료 크레딧은 빠져 있다. 실제 청구액은 각 콘솔에서 확인한다: X 개발자 콘솔(사용량·크레딧), AI 공급자 사용량 화면, Cloudflare R2 청구
- 요율표(설정 → 사용량·예산)는 확인일·출처와 함께 직접 갱신한다. 확인일이 없으면 금액을 계산하지 않는다. 링크가 들어간 X 게시는 단가가 훨씬 높다(2026-10 확인 기준 약 13배)
- 월 한도: "생성만 멈추기" 또는 "생성과 새 게시 모두 멈추기". 시작한 묶음의 답글은 한도 때문에 끊지 않는다. 80%에서 경고, 도달하면 중대 알림
- 결과를 모르는 요청은 과금됐을 수 있어 보수적으로 포함하고, 게시 기록에서 확인하면 정리된다

## 이미지 보관

- 게시가 끝난 묶음의 이미지는 마지막 완료 후 보관 일수(기본 14일)가 지나면 저장소에서 지운다(매시간 검사). 한 번도 게시하지 않은 이미지, 작성 중·예약·게시 중·확인 필요인 글이 쓰는 이미지는 지우지 않는다. 기록·원문·X 링크는 남는다. 설정 → 게시 후 이미지 보관에서 일수 변경
- 정리 실패는 알림 → 이미지 보관함 "정리 실패" 필터에서 다시 시도(자동으로도 1시간마다)
- "저장소에만 남은 파일"은 업로드 도중 끊겨 기록되지 않은 파일이다. 보관함의 보관 규칙 카드에서 하루 넘은 것만 지운다
- R2 공개 주소를 Cloudflare 캐시로 내보내면 지운 뒤에도 캐시 만료까지 보일 수 있다(필요하면 대시보드에서 캐시 삭제)

## 계정·키

- **관리자 비밀번호 변경**: `go run ./cmd/admin hash-password`로 새 해시 → `ADMIN_PASSWORD_HASH` 교체 → 재시작. 기존 로그인 세션까지 끊으려면 DB에서 `DELETE FROM sessions;`
- **TOKEN_ENCRYPTION_KEY**: X 토큰을 암호화하는 키. 비밀 저장소에 따로 보관한다. 잃어버리거나 바꾸면 저장된 연결을 읽을 수 없으니 X를 다시 연결한다(게시 기록 등 다른 데이터는 영향 없음)
- 비밀값은 환경변수에만 둔다. 화면·API·로그에 토큰·비밀번호·인증 헤더는 나오지 않는다

## 백업·복원·이전

앱의 영속 데이터는 **PostgreSQL 하나**다(설정·시간표·예약·글·게시 기록·X 연결(암호화)·알림·사용량). 이미지 파일은 R2에 있고, 게시 후 보관 기간이 지나면 지워지는 것이 정상이다.

```bash
# 백업 (DB에 접근할 수 있는 곳에서)
pg_dump --format=custom --no-owner --file=xauto-$(date +%Y%m%d).dump "$DATABASE_URL"
# 복원 (빈 DB에)
pg_restore --no-owner --dbname="$NEW_DATABASE_URL" xauto-YYYYMMDD.dump
```

- 이전: 새 DB로 복원 → 새 환경에 같은 `TOKEN_ENCRYPTION_KEY`·관리자 값을 넣고 기동(마이그레이션은 이미 적용된 것은 건너뛴다) → 홈·게시 기록 확인 → 이전 환경은 자동 운영을 먼저 멈춘 뒤 내린다(두 곳이 같은 계정에 게시하지 않게)
- KoDeploy 관리형 DB는 클러스터 안에서만 접근된다. 외부에서 `pg_dump`할 경로(포트 포워딩 등)는 KoDeploy 화면에서 제공하는지 확인이 필요하다(저장소에서 확인하지 못함). 백업이 중요하면 외부 관리형 PostgreSQL을 쓰는 것도 방법이다
- 덤프 파일에는 운영 데이터가 들어 있다. 저장소에 커밋하지 않는다

## 로그

- 표준 출력에 JSON 한 줄씩(`LOG_LEVEL`: debug·info·warn·error). 요청 로그(경로·상태·소요 시간·request_id), 작업 실패·결과 불명확·재시도, 이미지 정리 결과, 종료·시작
- 오류 응답의 `request_id`로 로그를 찾는다. 토큰·비밀번호·인증 헤더·사용자 원문은 로그에 남기지 않는다

## 장애 시 동작

| 상황 | 앱의 동작 |
|---|---|
| DB가 늦게 뜸·끊김 | 포트는 먼저 열고 `/readyz`는 503. 다시 연결될 때까지 재시도(재시작 반복 없음) |
| 재배포·종료 | 새 작업을 받지 않고 진행 중 작업 결과를 저장한 뒤 종료(유예 25초). 다음 시작 때 DB에서 이어 감 |
| 게시 중 끊김 | 보내던 부분은 "결과 확인 필요", 남은 답글은 확인 후 이어 감 |
| X 429·일시 오류 | 제한 해제 시각까지 기다렸다가 다시(보내지 않은 요청만) |
| X 401 | 토큰 한 번 갱신 후 다시. 갱신 거부면 연결 만료 + 알림 |
| AI 실패 | 재시도 상한까지, 이후 "생성 실패"와 알림. 결과를 모르는 생성 비용은 불명확으로 기록 |
| R2 실패 | 업로드는 오류로 보여 주고, 정리 삭제는 1시간 뒤 다시 |
